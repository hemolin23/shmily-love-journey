# Shmily 故事工作区

这里是空间改造前的叙事底稿。顺序固定为：

1. 真实材料梳理：聊天记录、图文回忆、后续补充的照片/音频/视频。
2. 故事选择：确定核心戏剧动作，而不是把所有日期平铺。
3. 剧本创作：梳理人物、关系弧光、结构、场景和对白。
4. 物件系统：每一件出现的东西都要有事实来源、剧情功能和情感回扣。
5. 空间化：最后才决定是多房间，还是一个可同时看到全部故事的总空间。

当前阶段：**剧本、剧本诊断与空间化实现均已完成。**

- [`story-core.md`](./story-core.md)：三个故事核心方案。
- [`story-synopsis.md`](./story-synopsis.md)：基于方案 A 的整体故事梗概。
- [`characters.md`](./characters.md)：两个人的 Want / Need / Arc 与关系弧光。
- [`world-and-backstory.md`](./world-and-backstory.md)：时代环境、关系前史与故事切入时刻。
- [`structure-outline.md`](./structure-outline.md)：开场钩子、四幕结构、高潮与结局。
- [`scene-list.md`](./scene-list.md)：十场戏的动作、物件、声音、时长与价值变化。
- [`checkpoint-01.md`](./checkpoint-01.md)：进入正式写作前的剧本记忆检查点。
- [`screenplay-scenes-01-02.md`](./screenplay-scenes-01-02.md)：第1—2场剧本，视频开场与上海初见。
- [`screenplay-scenes-03-10.md`](./screenplay-scenes-03-10.md)：第3—10场剧本，直至新的日常。
- [`script-doctor.md`](./script-doctor.md)：完整剧本诊断、修改决定与空间转换约束。
- `private/evidence-map.md`：本地私密证据表，不进入 Git。

最终空间采用一栋可同时看见六个房间的剖面屋。六个房间不是按日期平均切片，而是对应六次关系变化：允许靠近、生活预演、共同承受现实、共享时间、共同照顾、在不确定里陪伴。房间由一条“共同时间”的灯线依次点亮。
